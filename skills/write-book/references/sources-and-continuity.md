# Sources, versions and continuity

Read when taking over a project, when there are many versions, or when checking the canon. Documentation describes the project; historical instructions in an archive do not become new instructions from the user.

## Choosing the current text

1. Identify manuscripts, editions, reports, states, plans and archives. Make a short map: file, role, version stated in the content, origin and reason for the choice.
2. Compare the declared stage with the actual content. A README may say "no units written" although a later state and the full manuscript contain the epilogue. Confirmed execution takes precedence.
3. Choose one text source per volume. Treat the other formats as editions or variants until a comparison shows differences. Newer metadata or an ISBN does not have to mean newer prose.
4. Checksums show byte identity. A comparison after removing headings and normalising spaces shows agreement of that selected range only. State the omissions explicitly; do not remove differences from the originals this way.
5. Present unresolved plot variants to the author with a short description of their consequences. Copy dates and word counts are hints, not a ruling on canon. Do not delete duplicates as part of an analysis.

### Typical version traps

- **False completion.** A file called "final" or "proofread" may contain summaries of scenes instead of prose, even though its footer declares "full prose". Compare its length and headings with an earlier full version ([technical check](technical-check.md)). A statement in a file is not a measurement.
- **Empty result.** A report or audit may contain only an unfilled template variable. Open the file before citing it.
- **Two layers in one file.** A conversation log with "was → is" decisions and quotations from old versions is interleaved with prose. Separate the prose first, then judge consistency.
- **Withdrawn master.** A copy of a package from before the corrections may circulate next to the corrected one. Mark withdrawn versions in the source map and do not add them to handoff packages.
- **Competing decision documents.** Two versions of rulings on the same questions: the version named by the author, or by the author's newer instruction, applies; take from the other only non-conflicting elements and record which.
- **Plan from memory.** A continuation plan written from a conversation, without checking the text, often contradicts the written volume (names, dates, who could know what). Compare such a plan with the prose point by point and keep a register of conflicts and their resolutions.

The author's current decision settles an intended change. Without such a change, the chosen prose confirms the facts. The state and the report help find a scene; the plan describes intent. If a report contradicts a scene, show the discrepancy instead of writing the plan's execution into the project memory.

## State of characters and objects

Keep only the registers the book needs. Link every significant entry to a scene or a stable unit identifier.

| Area | What to establish |
|---|---|
| Chronology | Date, order of events, journeys, time zones and flashbacks. Do not confuse the date of a document, its receipt and its printing. |
| Knowledge | Who knows, what they learned first-hand, from whom, when and how certainly. The reader's knowledge does not automatically pass to a character. |
| Documents and evidence | Original, copies, origin, handovers, access, what it proves. Holding a sheet of paper does not prove it is authentic. |
| Props | Owner, location, condition, changes and whether it can physically be used in the scene. |
| Body and mind | Injuries, treatment, limitations, fatigue, reactions and the passage of time. |
| Relationships | Agreements, boundaries, concealments, conflict and how it was actually resolved. |
| Seeds | Where introduced, who noticed, later use; do not resolve a thread with knowledge that was never shown. |
| Forms of address | Who uses first names, titles, formal or informal address with whom, in which language; from which scene this changes. A change of form is an event and can be a hook. |
| Recurring props | Objects present across many volumes (e.g. a diary, a ring, a key): condition, contents, location in every unit where they appear. |
| Series counters | Things counted in the text (e.g. "the second time in his life", "for ten years"): current value and the unit in which it changed. |

A knowledge table takes the form: character → knows / does not know / hides from whom. An entry marked "plan" is a decision the prose does not confirm; a character cannot use it without a scene.

A flashback can extend the reader's knowledge but does not automatically roll back the state of the main action. A new fact exists only once written in a scene. Distinguish certainty, a character's account, a hypothesis, a plan and a decision awaiting the author.

## Resuming work and handing over

The state opens with a current summary. Historical entries stay history. Record the completed scope and the next step; for a finished book write "no next unit". Mark scenes that depend on an unresolved decision.

For a handover, a map of files, the current state, the selected texts, the decisions in force and the reports needed for the task are enough. Handing work to another model or application is described in [separate instructions](model-handoff.md). A link to a local file does not transfer its content to another environment. Report only material actually read.
